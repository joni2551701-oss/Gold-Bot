# ADR-002 — Universal Screen Identity

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002B (Navigation Architecture) review.

## Decision

Every screen gets exactly one ID, stable across every platform:

```
dashboard.home
dashboard.analytics
signals.list
signals.details
settings.main
settings.notifications
profile.main
```

The ID never changes per platform — Telegram, Android, iOS, Desktop,
and Mini App all address the same screen by the same string.

## Why

Without one stable ID, each platform would need its own mapping table
translating its own local screen identifier into "what this actually
means" — exactly the kind of per-platform divergence ADR-001 exists to
prevent.

## Convention

Dotted, lowercase, `<category>.<name>` shape (e.g. `settings.language`,
`signals.upgrade`) — matches the category concept already in
`docs/NAVIGATION_ARCHITECTURE.md` §2 (Screen Model) and generalizes
today's real Telegram sections (Main/Settings/Admin/Owner/Profile/
Signals) into the same convention, e.g. today's `/language` command
becomes `settings.language`.

## Impact

- `platforms/navigation_model.py` — `NavigationNode.id` (and any
  successor Screen concept) follows this convention from TASK-002C
  onward.
- `platforms/menu_registry.py` — `MenuDefinition.id` follows it too.

## Status

Approved — Director decision, effective immediately, applies from
TASK-002C onward.
