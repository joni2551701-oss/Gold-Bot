# ADR-004 — Navigation Event Bus

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002B (Navigation Architecture) review.

## Decision

Every platform emits the same event vocabulary:

```
ScreenOpened
ScreenClosed
BackPressed
PermissionDenied
NavigationFailed
DeepLinkOpened
SessionExpired
```

**TASK-002C builds the interface only — no dispatch/pub-sub
implementation, no wired consumer.** This is a contract (an event
shape and a fixed vocabulary), the same "foundation, not wired yet"
posture every other module in this repo takes at introduction
(`assets/`, `configuration/`, `platforms/` itself in TASK-001).

## Why

A shared event vocabulary is what lets a future Analytics or AI
consumer observe navigation behavior across every platform uniformly,
without each platform inventing its own ad hoc logging shape.

## Impact

- New, genuinely unwired contract in `platforms/` (Article 11 audit:
  no existing Foundation/Manager/Contract/Model/Capability/Registry
  covers a navigation event vocabulary).
- Future consumers (named in `docs/NAVIGATION_ARCHITECTURE.md`'s
  Future Expansion section): AI Assistant, Academy/Education, a future
  Marketplace module — none wired today.
- Adjacent to, but not part of, the existing `monitoring/`/`analytics/`
  foundations — whether/how those ever read these events is a future,
  separately-scoped decision.

## Status

Approved — Director decision, effective immediately. Interface only;
implementation deferred to TASK-002D or later.
