# ADR-009 — CI Supersession Rule

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002D freeze review — resolving the CI #158/#159
question the Worker flagged rather than silently deciding.

## Decision

A cancelled CI run does not permanently block a task if:

1. The prior run was cancelled **only** because a new push superseded
   it (GitHub's own `concurrency: cancel-in-progress: true` on
   `ci.yml`) — not because it failed.
2. The subsequent run validates the **same codebase** the cancelled
   run would have (identical tree, or with only a non-functional
   change — e.g. a documentation fix, no code) — or a real code change
   plus that same content.
3. That subsequent run completes with `success`.

When all three hold, **the later successful CI run is the official
validation** for the cancelled run's content — a task is not
artificially blocked by a cancellation that was never a failure.

## Why

Resource efficiency (no re-running an already-cancelled check for no
reason) and correctness (a task should not sit blocked by a "failure"
that was never actually a failure — it was pre-empted by a later push
that itself passed).

## Precedent this formalizes

TASK-002D: `ci.yml` run #158 (commit `b366971`) was cancelled when
run #159 (`8adf53b`, the same tree plus one non-code changelog line)
was pushed before #158 finished. Run #159 completed `success`. Per
this rule, #159's success is TASK-002D's official CI validation —
TASK-002D is `✅ APPROVED`, `Frozen`, effective this decision.

## Applies to

Every future task, not just TASK-002D — recorded as a standing rule in
`docs/PLATFORM_WORKFLOW.md`'s Freeze Checklist section ("CI Passed" is
satisfied by a superseding run under the conditions above, not only by
the exact run number a task's brief happened to name).
