# ADR-008 — Navigation Result

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002D review. **Governs future Navigation work — see
"Applies to" below; does not retroactively rewrite already-approved
TASK-002D content.**

## Decision

Navigation never returns a plain true/false. The standard result model
is a fixed outcome vocabulary:

```
SUCCESS
BLOCKED
NOT_FOUND
PERMISSION_DENIED
FAILED
REDIRECTED
```

## Why

A bare boolean collapses distinct failure reasons into one bit — a
caller (or a future Analytics consumer) cannot tell "screen doesn't
exist" from "user lacked permission" from "navigation redirected
elsewhere" without inspecting a separate, informally-shaped field.

## Applies to

Future Navigation implementation work. `platform_layer/platform_service/navigation_core.py`'s
current `NavigationResult.ok: bool` (TASK-002D, pending CI
confirmation) is exactly the shape this ADR moves away from —
`result.event.event_type` already distinguishes `NAVIGATION_FAILED`
from `PERMISSION_DENIED` today, so the underlying information already
exists; this ADR calls for promoting that distinction to
`NavigationResult`'s own primary field, replacing `ok: bool` with an
outcome enum. That is a breaking change to a contract introduced this
same review cycle, so it is explicitly deferred to its own task
(No Silent Decisions Policy) rather than applied retroactively here,
which would edit content already marked `✅ APPROVED` in this same
review.

## Status

Approved — Director decision, effective immediately as a governing
principle. Implementation (replacing `NavigationResult.ok` with an
outcome enum) is a future task, not applied to TASK-002D's own
already-reviewed code in this cycle.
