# ADR-011 — Security Review Layer

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002E security review — the Director's response to
the `has_sufficient_permission()` observation, formalizing the review
practice that found it into a standing requirement.

**Numbering note**: the Director's review named this decision
"ADR-010"; recorded here as **ADR-011**, since ADR-010 is used for the
companion Fail Closed Permission Policy decision from the same review
(see `communication/decisions/ADR-010.md`'s own numbering note for why).

## Decision

From this point forward, every task whose scope touches Permission,
Authentication, Authorization, Session, or Navigation code must
include a **Security Review** section in its end-of-task report,
covering:

- **Attack Surface** — what input/state an attacker could control.
- **Failure Modes** — what happens on unknown/invalid/missing/
  malformed input.
- **Fail Open / Fail Closed** — which one the code actually does,
  for every checked path, not just the common one.
- **Abuse Scenarios** — concrete, specific misuse cases, not a generic
  disclaimer.
- **Recommendations** — fix now (if in scope and authorized) or defer
  to a tracked Security Backlog entry (if not).

## Why

TASK-002E's validation work surfaced a real fail-open condition
(`has_sufficient_permission()`'s required-tier direction, see
ADR-010) precisely because the task's test-writing process asked
"what happens on invalid input" as a matter of course. Making that
question a mandatory report section, rather than something that only
surfaces when a worker happens to write an edge-case test, is how this
class of finding gets caught consistently instead of by chance.

## Applies to

Every Permission, Authentication, Authorization, Session, and
Navigation module's task report, starting with TASK-002F (Navigation
Foundation Final Audit) — which the Director has scoped to include a
Security Audit section built on this ADR. Recorded as a standing rule
in `docs/PLATFORM_WORKFLOW.md`.

## Status

Approved — Director decision, effective immediately.
