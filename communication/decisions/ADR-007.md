# ADR-007 — Navigation Context

**Type**: Architecture Decision Record (Director-issued, binding).
**Context**: TASK-002D review. **Governs future Navigation work — see
"Applies to" below; does not retroactively rewrite already-approved
TASK-002D content.**

## Decision

Navigation is never just a Screen. Every screen is opened with a
Context:

```
screen_id
session_id
parameters
source
timestamp
navigation_reason
```

## Why

`screen_id`/`session_id` alone answer "where," not "why" or "from
where" — future Analytics, AI, Audit, and Debug consumers all need the
richer context (`source`: what screen/action triggered this
navigation; `navigation_reason`: user tap vs. deep link vs. permission
redirect; `parameters`: e.g. which signal id a `signals.details`
screen was opened for; `timestamp`: when).

## Applies to

Future Navigation implementation work. `platforms/navigation_events.py`'s
current `NavigationEvent` (ADR-004, TASK-002C) carries `screen_id`/
`platform`/`details` only — a narrower shape than this Context. Adding
the fields above is an additive change to an existing contract once
authorized as its own task (No Silent Decisions Policy — `NavigationEvent`
is already a public contract other tests depend on; widening it is
not silently done here).

## Status

Approved — Director decision, effective immediately as a governing
principle. Implementation against `platforms/navigation_events.py` (or
a new companion `NavigationContext` dataclass) is a future task.
