# DD-030 — MarketMemory is not a Singleton — MarketMemoryRegistry

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1. **Phase**: GoldBot v1.1 Phase 1 — Market Data Foundation.
**Context**: The initial design implied a single process-wide MarketMemory.

## Decision

`MarketMemory` must **not** be bound to a singleton. A
**`MarketMemoryRegistry`** owns one memory per asset:

    MarketMemoryRegistry
      -> MarketMemory(XAUUSD)
      -> MarketMemory(BTCUSD)
      -> MarketMemory(EURUSD) ...

so Gold, BTC, EURUSD, NASDAQ, SP500 can run concurrently. The Market Data
Foundation must be **asset-general**, not XAUUSD-only:
Asset -> MarketMemory -> PriceStream -> History -> Chart -> AI.

## Why

Hard-coding one asset would force an architecture rewrite to add
instruments later. A registry makes multi-asset a thin indirection; only
XAUUSD is wired first, others are config-added.

## Status

**Approved — binding for the Market Data Foundation.** Reflected in the
architecture document (§2 (Multi-asset topology)).

## Applies to

The GoldBot v1.1 Market Data Foundation (`data/` layer) and every future
component that reads market data through it.
