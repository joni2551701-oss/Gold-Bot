# DD-036 — Branch Strategy (formalized)

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1. Formalizes ORDER-026.
**Context**: After the v1.0.0 consolidation onto a single `main`, the
forward development model needed to be a durable governance rule, not just
an order.

## Decision

All new development happens on temporary branches:

- `feature/*` — new features / foundations
- `fix/*` — bug fixes
- `hotfix/*` — urgent production fixes

**`main` is updated only through a Pull Request merge.** No direct pushes
of new work to `main`. Long-lived parallel branches (the retired
`claude/*` style) are no longer used.

Standard flow for every future branch:

```
feature|fix|hotfix/* → Pull Request → CI → Director Review → Merge → main
```

## Why

A single official `main` plus short-lived PR-merged branches gives a clean,
auditable history, a review gate before anything reaches `main`, and CI on
every change — the model the v1.0.0 consolidation set up. It replaces the
ad-hoc long-lived-branch pattern that produced the divergence Recovery had
to untangle.

## Status

**Approved — standing rule for all future development.**

## Applies to

Every branch and merge in the repository from this decision onward; the CI
trigger configuration (`.github/workflows/ci.yml` covers
`main`, `feature/**`, `fix/**`, `hotfix/**`).
