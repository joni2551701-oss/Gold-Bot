# DD-001 — Audit Acceptance & Flag Rulings

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1 (FROZEN).
**Context**: The Director's final ruling on the four read-only audits
(Repository, Structure, Validation, Migration Plan) produced by the
Core and Platform Worker functions, and on the two governance flags the
Worker raised under the No Silent Decisions Policy.

## Decision

**1. Audits — ACCEPTED (all four).**

| Audit | Ruling | Key accepted findings |
|-------|--------|-----------------------|
| Repository Audit | ✅ ACCEPTED | production (`claude/code-analysis-optimization-pwfo3q`) is the canonical v1 branch; `main` is stale, not production; `strategy_layer/strategy_manager/strategy_manager.py` is the single merge blocker; Recovery is technically bounded. |
| Structure Audit | ✅ ACCEPTED | 36 top-level packages; layering intact; deployment files present; `.env.example` documented; no structure refactor required. |
| Validation | ✅ ACCEPTED | 4689 tests pass; 0 pyflakes; compile clean; `main.py` smoke = expected fail-closed (no API key). |
| Migration Plan | ✅ ACCEPTED | `docs/governance/MIGRATION_PLAN.md` accepted as SSOT; no competing migration document is to be written. |

**2. FLAG 1 — QA Worker / Release Worker roles — REJECTED (for now).**
Governance v1.1 is **not** amended. The role model remains:

```
Director
   │
 ┌─┴──────────────┐
 Core Worker   Platform Worker
```

QA and Release are **functions, not roles**. The Core Worker performs
audit; the Platform Worker performs audit; Validation and Release
remain temporary functions. No new role is added until a deliberate
Governance v1.2 amendment.

**3. FLAG 2 — no Migration approval before Recovery — ACCEPTED.**
The sequence is fixed and may not be reordered:

```
Recovery → Verification → Recovery Approved → Migration → main → tag v1.0.0
```

Accordingly the Migration status is set to:

> **Migration — APPROVED IN PRINCIPLE — STATUS: WAITING FOR RECOVERY.**

## Why

The audit conclusions matched the live Git state on independent
verification, so acceptance is evidence-based, not procedural. FLAG 1
is rejected now because adding governed roles is a Constitution-level
amendment (v1.1 → v1.2) that must be taken deliberately, not created
implicitly by addressing work to role names that do not yet exist.
FLAG 2 is accepted because approving a merge *into* an unrecovered
`main` (which still carries the U+2060 rename/rename conflict) would
approve the exact defect Recovery exists to remove — so "Approved in
Principle, pending Recovery" is the only honest status.

## Status

**Approved — binding for GoldBot v1.** Migration remains gated on
Recovery completion; no repository-level Migration action proceeds
until the Recovery Report is Director-approved.

## Applies to

The Recovery → Migration → Release sequence; the Governance v1.1 role
model; all audit acceptance for the current v1 cycle.
