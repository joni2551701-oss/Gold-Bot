# DD-038 — Architecture-First Development

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1. Standing process rule.
**Context**: Before GoldBot v1.1 Phase 1 implementation begins, the Director
fixes the development order that every new module follows, so that code is
always preceded by an approved architecture and design.

## Decision

Every new module is developed in this order:

```
1. Architecture
2. Design Review
3. Documentation
4. Implementation
5. Testing
6. Integration
7. Merge
```

This sequence is the **standard for all future phases**, not just v1.1
Phase 1. Implementation does not begin until the architecture and its design
are reviewed and documented; merge is the final step, via a PR (DD-036).

## Why

Architecture-first prevents the drift and rework that ad-hoc coding causes.
It guarantees each module is a deliberate realization of an approved design,
keeps documentation in lockstep with code, and preserves the audit trail
GoldBot's governance depends on. It is the same discipline that produced the
Market Data Foundation architecture before any of its code.

## Status

**Approved — standing rule for all future development.** Recorded as a
post-merge governance update (deferred during the PR #3 CI gate, per the
Director's decision, to avoid disturbing that gate).

## Applies to

Every new module in every phase from this decision onward.
