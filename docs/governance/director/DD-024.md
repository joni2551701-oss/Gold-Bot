# DD-024 — Repository Consolidation & GoldBot v1.0.0 Release

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1 (FROZEN).
**Numbering note**: the Director assigned the identifier **DD-024** directly
(from the Director decision stream), leaving DD-005…DD-023 reserved/unused
in this registry. Recorded under the assigned number verbatim rather than
renumbered — flagged here per the No Silent Decisions Policy.
**Context**: After the RECOVERY-BLOCKER-001 analysis showed Recovery was
infrastructure-blocked (git-proxy denies `refs/tags/*`), the Director
chose to consolidate the repository directly onto a single official `main`
instead of repairing the stale one.

## Decision

**1. Recovery — SKIPPED. DD-001's Recovery requirement is superseded.**
Recovery is no longer a mandatory stage. Rationale: the old `main` is
retired and archived, not repaired; the U+2060 corruption existed *only*
on old `main`; a healthy canonical GoldBot v1.0.0 already existed on a
clean branch. Repairing the retired `main` would add no value to the final
repository. **DD-001's Migration-after-Recovery gate is replaced by this
decision.**

**2. Migration Strategy — PATH 2 approved.** GoldBot v1.0.0 becomes the
repository's new official state on `main`; the previous `main` is archived
as part of repository history.

**3. Branch Consolidation — authorized.** Repository consolidation, branch
migration, branch archive, branch delete (only after archives are
confirmed), default-branch update, and branch-protection configuration are
all Director-authorized.

**4. Force Push — avoided.** A safe, history-preserving, non-force method
was required and used (a two-parent forward merge commit whose tree equals
the v1.0.0 source). Force push was **not** used.

**5. Release Tag — deferred.** The `v1.0.0` tag push is blocked by the
git-proxy (HTTP 403, `refs/tags/*`). This does **not** block the release.
Release status: **released without remote tag**; the tag is to be created
later by an Authorized Operator.

**6. Final Repository State (target):**

```
main                         GoldBot v1.0.0 (single official development branch)
archive/main-pre-v1          retired previous main
archive/claude-code-analysis retired canonical production
archive/claude-trading-ai    retired working / v1.0.0 source
```

## Execution outcome (as recorded at consolidation time)

- `main` migrated to `8639e2b` — GoldBot v1.0.0, content-verified identical
  to the v1.0.0 source, 0 U+2060 filenames, 0 conflicts vs canonical.
- Non-force fast-forward push; both prior lineages preserved as ancestors;
  no commit or history lost.
- Three archive branches created and verified.
- CI on `main` (`8639e2b`, run #183) returned **success**.
- **Outstanding (infrastructure/authority-bound):** deletion of the two
  legacy `claude/*` branches is blocked from the Worker session (git-proxy
  HTTP 403 on ref deletion) → **Authorized Operator**; branch protection →
  **Repository Owner**.

## Companion orders

- **ORDER-025** — after CI `#183` success: delete the legacy `claude/*`
  branches (Authorized Operator), re-run Repository Health Verification,
  produce the Final Release Report.
- **ORDER-026** — repository branch model going forward: `main` is the sole
  official development branch; all new work happens on temporary
  `feature/*`, `fix/*`, `hotfix/*` branches merged back into `main`;
  long-lived parallel branches (`claude/*`-style) are no longer used.

## Why

The infrastructure block on tag/deletion pushes made the original
Recovery-then-Migration sequence unable to complete from the working
session, while a clean v1.0.0 already existed on a branch. Consolidating
directly onto `main` — archiving the old branches first, using a non-force
merge — reaches the desired single-branch end state with zero history loss
and without spending effort repairing content that is being retired.

## Status

**Approved — executed. Binding for GoldBot v1.0.0.** Supersedes DD-001's
Recovery requirement. Residual cleanup (legacy deletion, branch protection)
delegated to the Authorized Operator / Repository Owner.

## Applies to

The repository branch topology; the Recovery/Migration sequence; the
GoldBot v1.0.0 release; the forward branch model (ORDER-026).
