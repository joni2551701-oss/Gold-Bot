# DD-003 — `main` Branch Status

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1 (FROZEN).
**Context**: Companion to DD-002. Having named production the canonical
source, the Director fixes the status of the current `main` branch so
it is not mistaken for any of the standard branch roles during the
Recovery/Migration window.

## Decision

The current `main` branch is **none of** the following:

- not a **development** branch;
- not a **production** branch;
- not a **release** branch.

It is a **temporary holding branch**, retained only because Recovery
has not yet completed. Once Recovery is finished, `main` transitions
via:

```
production → Migration → main
```

after which `main` becomes the reconciled, canonical release line.

## Why

The current `main` (`5618adec`) is stale relative to production
(DD-002) and still carries the U+2060 filename corruption that blocks a
clean merge. Treating it as a live development/production/release line
would misrepresent the repository. Declaring it a temporary holding
branch keeps the repository state honest until Migration replaces its
contents from the canonical source.

## Status

**Approved — binding until Migration completes.** Superseded in effect
(not in record) once `production → Migration → main` executes and `main`
becomes the reconciled release line.

## Applies to

All interpretation of `main`'s role during the Recovery → Migration
window; any tooling, documentation, or reviewer that must know what
`main` currently represents.
