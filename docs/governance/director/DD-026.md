# DD-026 — M1 Timeframe Mandatory (default ON)

**Type**: Director Decision Record (Director-issued, binding).
**Governance**: v1.1. **Phase**: GoldBot v1.1 Phase 1 — Market Data Foundation.
**Context**: The v1.1 Phase 1 architecture proposed M1 default-OFF to save API budget.

## Decision

**M1 is a mandatory timeframe — default ON.** The Worker's
recommendation to keep M1 default-OFF is **REJECTED**. All six timeframes
are ON by default:

    M1  M5  M15  H1  H4  D1

GoldBot's strategies — Liquidity Sweep, SMC, ICT, Entry Precision — do not
work fully without M1. API optimization is achieved by other means (see
Why), not by dropping M1.

## Why

M1 is structurally required by the entry-precision strategies. The API
cost concern is resolved differently: a single live price stream feeds the
CandleBuilder, which aggregates M1..D1 **in memory** — so M1 adds CPU/RAM
cost, not extra API polling. Historical M1 is one bootstrap call like any
other TF.

## Status

**Approved — binding for the Market Data Foundation.** Reflected in the
architecture document (§5, §17 (API Optimization) of the architecture doc).

## Applies to

The GoldBot v1.1 Market Data Foundation (`data/` layer) and every future
component that reads market data through it.
