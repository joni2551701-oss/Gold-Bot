# Explainability Layer Foundation (Phase A9)

## Purpose

Turns a signal candidate's already-computed context into human-
readable reasons — answering "why did this signal fire?" for a user
or a future AI provider, without generating a signal, approving one,
or computing a new confidence value. **Explainability is presentation
of existing reasoning, not new reasoning.**

Before this phase, GoldBot could say:
```
BUY
Confidence 85
```
After this phase, the same signal carries:
```
BUY
Reasons:
✓ HTF bullish bias
✓ HH/HL structure
✓ Liquidity sweep detected
✓ FVG reaction
✓ London session
Quality: A+
Confidence: 85%
```

## What it does

`signals/explainability.py`'s `explain_signal(signal, context,
quality)` produces a `SignalExplanation`:

```python
@dataclass(frozen=True)
class SignalExplanation:
    direction: str            # "BUY"/"SELL"/"NONE"
    reasons: Sequence[str]     # human-readable, in the order found
    quality: str               # the letter grade, e.g. "A+"
    confidence: float          # signal.confidence * 100
```

**No new detection logic is introduced.** Every reason comes from
data already computed elsewhere:

1. **Signal Quality Score's `criteria_met`** (Phase A4) — the primary
   source. Each already-computed criterion name is translated into a
   direction-aware, human-readable phrase:

   | Criterion | BUY phrase | SELL phrase |
   |---|---|---|
   | `HTF_ALIGNED` | "HTF bullish bias" | "HTF bearish bias" |
   | `STRUCTURE_ALIGNED` | "HH/HL structure" | "LH/LL structure" |
   | `LIQUIDITY_SWEPT` | "Liquidity sweep detected" | (same) |
   | `ORDER_BLOCK_ALIGNED` | "Order block reaction" | (same) |
   | `FVG_ALIGNED` | "FVG reaction" | (same) |

   No alignment check is re-implemented — `explain_signal()` never
   re-derives whether HTF/Structure/Liquidity/OB/FVG actually align;
   it only reads Signal Quality Score's answer and rephrases it.

2. **Wyckoff** (Phase A5) — the most recent `WyckoffEvent`, if its
   phase agrees with the signal's direction (`ACCUMULATION` for BUY,
   `DISTRIBUTION` for SELL): `"Wyckoff Spring (Accumulation)"` /
   `"Wyckoff Upthrust (Distribution)"`. A disagreeing event (e.g. an
   Upthrust for a BUY signal) is silently excluded — it isn't a
   reason to trust this signal.

3. **Session** (Phase A6) — the current session, reported regardless
   of direction (session has no bullish/bearish reading of its own):
   `"London session"`, `"Asia session"`, `"London New York Overlap session"`.

4. **Market Regime** (Phase A7) — only when `TRENDING` and the
   direction agrees: `"Market regime: TRENDING (BULLISH)"`.

`confidence` is `signal.confidence * 100`, relayed exactly as
generated by the strategy — never recomputed, never blended with
`quality.score` or anything else. This is deliberate: Explainability
runs *before* `DecisionEngine.evaluate()` in the pipeline (see
"Pipeline position" below), so no blended/final confidence exists yet
to report even if this module wanted to.

## What it does NOT do

- Does not generate a `BUY`/`SELL` signal, and is not itself a
  strategy — `strategies/*.py` and `signals/signal_engine.py` are
  unmodified.
- Does not approve or reject a signal — `decision/decision_engine.py`
  is completely unmodified; `explain_signal()`'s output isn't even
  passed into it in this phase.
- Does not compute a new confidence value — `SignalCandidate.confidence`
  is relayed, not recomputed.
- Does not call an AI model — no GPT/Gemini integration; `ai/` is
  unmodified.
- Does not change the Telegram message format — `telegram/signal_formatter.py`
  is unmodified; enriching the actual delivered message with
  `SignalExplanation` is a future, separate step.
- Does not persist explanations — no schema change, no new table.

## Pipeline position

```
Strategy Engine
      |
      v
Signal Engine           -- aggregates candidates (unchanged)
      |
      v
Signal Quality Score     -- A+/A/B/C grade + criteria_met (Phase A4)
      |
      v
Explainability           -- criteria_met -> phrases + Wyckoff/
      |                     Session/Regime context (Phase A9, NEW)
      v
AI Layer / Decision Engine   -- unchanged; does not read explanations
```

New `core/pipeline.py` stage immediately after `signal_quality`
(computed per candidate, same order as `"signals"`/`"quality_results"`).
`TradingPipeline.run()`'s result dict gains one new key,
`"explanations"`. No existing stage's inputs, outputs, or ordering
changed.

## Structure summary

| Field | Example |
|---|---|
| `direction` | `"BUY"` |
| `reasons` | `("HTF bullish bias", "HH/HL structure", "Liquidity sweep detected", "FVG reaction", "London session")` |
| `quality` | `"A+"` |
| `confidence` | `85.0` |

An empty `reasons` tuple is a valid, expected result (nothing
supported this signal) — not an error. A missing/empty context
(no Wyckoff events, no session data, `UNKNOWN` market regime) simply
omits those specific reasons rather than raising.

## How AI will use this in the future

`ai/ai_analyzer.py`'s `AIAnalyzer.analyze()` is still a permanent-
reject heuristic stub (`docs/AI_ARCHITECTURE.md`) — this phase does
not connect `SignalExplanation` to it. But a structured, human-
readable reason list is exactly the shape a future real AI provider's
prompt would want: instead of re-deriving "why does this setup look
good" from raw `ContextSnapshot` fields on every call, a future
`AIAnalyzer` implementation could read `SignalExplanation.reasons`
directly as part of its prompt context, and potentially reason about
*which* factors were present rather than only a bare confidence
number. `SignalExplanation` is already sitting in `run()`'s result
dict, alongside `context_layer.trend.market_regime` (`docs/MARKET_REGIME.md`'s
own "Significance for AI" section makes the same point) — no new
plumbing needed to make it available once a real AI implementation
exists, only a decision (out of this phase's scope) to read it.

A second, more direct future use: enriching the actual Telegram
message (`telegram/signal_formatter.py`) with the reasons list, so a
trader sees *why* a signal fired, not only that it did — also not
implemented in this phase.
